# BLK-013 — Patch Python inline : `\r\n` échappé, assert en échec

| Friction                                                                                                                                                                                                                                                                             | Cause réelle                                                                                                                                                  | Solution                                                                                                                                                                                           | Statut |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------ |
| Un script Python passé en heredoc pour remplacer des blocs de `src/dxf.ts` échoue sur l'assert du bloc contenant `join('\r\n')` ; la commande de diagnostic suivante (`grep … \| od -c`) reste bloquée 120 s. Le même souci est revenu au `memory-close` (heredoc avec apostrophes). | Échappements imbriqués heredoc → chaîne Python : le `\r\n` littéral du code source n'est plus reproduit à l'identique, et les apostrophes cassent le heredoc. | Script de patch écrit dans un fichier `.py` du scratchpad (séquence construite avec `BS = '\\'`), un `assert` par bloc pour échouer sans rien écrire ; fichiers mémoire écrits avec l'outil Write. | résolu |
