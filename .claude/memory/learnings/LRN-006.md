# LRN-006 — shadcn CLI 4.21 Windows : `cn` npm au lieu de `@/lib/utils`

| Pattern observé | Contexte | Application future |
| --- | --- | --- |
| Sous Windows, `shadcn@4.21.5 init` / `add` génère des composants qui importent `from "cn"`, installe le paquet npm `cn` à la place de `clsx` + `tailwind-merge`, et écrase `src/lib/utils.ts` par un ré-export circulaire `export { cn } from "@/lib/utils"`. | Migration de l'UI vers shadcn sur escalier-beton (Vite, alias `@` ajouté dans `tsconfig.json` + `vite.config.ts`). | Après chaque `init` / `add` : `grep -rl 'from "cn"' src \| xargs sed -i 's\|from "cn"\|from "@/lib/utils"\|'`, puis `pnpm remove cn && pnpm add clsx tailwind-merge`, et réécrire `utils.ts` avec `twMerge(clsx(inputs))`. Voir aussi GLRN-121 (dossier `@\`) et GLRN-178 (`paths` dans le tsconfig racine). |
