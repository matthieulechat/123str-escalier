# LRN-021 — Valider un DXF hors AutoCAD : `ezdxf recover`

**Pattern observé** : `python -m pip install --target <scratchpad>/pylib ezdxf`, puis avec `PYTHONPATH=pylib` : `from ezdxf import recover; doc, a = recover.readfile('out.dxf')` → `len(a.errors)`, `doc.styles`, `doc.modelspace().query('TEXT')`. libredwg-web renvoie 0 entité sur nos DXF R12 minimaux (sans HEADER) : inutilisable comme validateur.

**Contexte** : Ajout d'une table `STYLE` et d'entités `SOLID` dans l'export R12, impossible à ouvrir dans AutoCAD depuis le PC perso.

**Application future** : Après tout changement de structure du DXF (tables, nouveaux types d'entité), passer `ezdxf recover` avant de livrer ; compléter par l'aperçu SVG de [LRN-017](LRN-017.md) pour le visuel ; validation finale du rendu (polices, oblique) dans AutoCAD au bureau.

**Mise à jour 2026-10-18** : `pip install ezdxf matplotlib` suffit, puis `doc = ezdxf.readfile(f)` et `doc.audit().errors` (les `DIMENSION` et blocs R12 sont lus, et `d.get_measurement()` donne la valeur). Aperçu PNG : `ezdxf.addons.drawing.matplotlib.qsave(msp, 'out.png', bg='#000000')`, **sur fond noir** : sur fond blanc, les calques sans table restent blancs sur blanc. Compléter par un contrôle des traits (segments nuls, doublons, bouts béton qui ne touchent aucun autre trait), qui a trouvé les traits nuls aux angles du jour droit.
