# LRN-018 — `grep` via rtk : `\|` non géré, « 0 matches » trompeur

**Pattern observé** : Le hook rtk réécrit `grep` (repli sans ripgrep) : l'alternance BRE `|` n'y est pas comprise et renvoie « 0 matches » au lieu d'une erreur ; `grep -E` avec `\(` échoue aussi (« Unmatched ( »).

**Contexte** : Un `grep` de contrôle après un `sed` a affiché 0 match alors que le `sed` avait réussi ; l'`Edit` suivant a échoué sur une chaîne déjà remplacée.

**Application future** : Vérifier une modification avec l'outil Grep (regex ripgrep) ou `grep -E 'a

**undefined** : b'` sans parenthèses échappées ; ne pas conclure qu'une édition a échoué sur un « 0 matches » sans relire le fichier.
